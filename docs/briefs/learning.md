## Requirements
- **One reusable view for live and preview.** Export `CourseView` (course page body) and `PlayerView` (step player) taking already-loaded content plus `PlayerMode` (`src/components/course/types.ts`). Live mode reads and writes real progress. Preview mode (staff, drafts) takes its content as a prop, keeps progress in client state only and writes nothing. Every piece of course text is rendered through `EditableText` / `EditableBlock` with an id-based `path`, so Studio can edit inline. The Studio content slice mounts these views; do not build preview routes yourself.
- Always send learners `toLearnerCourse(content)`: never quiz answers, option feedback before an attempt, `coachContext`, editor notes or verify flags.
- Catalogue: Postgres full-text search; filters for category, pathway, difficulty, time, tool, free; sorts For you, New, Popular (aggregate counts only), Shortest. `pathway` only orders and recommends. For a learner it never returns a course above their age (`minAge` is hard, whatever the pathway), nor one in a parent-blocked category or list. Paid courses on Free show locked with `AskParentToUnlock` — never a price. Live statuses are `LIVE_COURSE_STATUSES`.
- Course page: trailer (native video, captions, transcript, no autoplay), what you make, modules and timings, skills and careers, `ToolsYouNeed`, rubric preview, watch-outs, last-verified dates, Start or Continue, wishlist, Report.
- Start and every step load, autosave and quiz attempt run `checkStart` and `checkLearningAllowed` on the server; a direct link is refused the same way as the button. Render each blocker with its message and its "ask a parent" action. Starting pins `enrolment.course_version_id`; resume works from any device.
- Player step types: `video`, `read`, `setup_guide` (the guide's steps with screenshots and alt text, tick-off, "This doesn't match what I see" → `ReportControl` with `guide_mismatch`), `external_task` (instructions, `ExternalToolLink` using the Register allow-list, "I've done this" confirmation; the player stays usable while the tool is open in another tab), `quiz` (graded on the server; feedback shown after answering; retries; pass mark), `ethics_checkpoint` and `reflection` (free text, autosaved, private to the learner and never shown to parents verbatim unless the spec says so — check), `checkpoint`, and `upload` / `submit` by mounting the evidence components. Completion rules per the model. Tiered hints revealed one at a time, with Coach offered after the hints. A disabled step (`step.disabled`) shows a short notice and can be skipped; a taken-down course shows a clear notice and nothing else.
- Progress and notes save automatically (debounced, retried, with a visible "Saved" status in a live region) and never lose work when the cap is reached: save first, then stop.
- Time: a heartbeat counts active time only while the tab is visible; the daily cap is a hard stop with a friendly screen; quiet hours block learning and notifications; both come from `getControls`.
- Learner home: continue learning, made for you (interests), new this week, saved, notices. Accessible, fast on a 4 GB Chromebook: Server Components by default, small client islands, no layout shift.
- No public profiles, no feeds, no comments, no leaderboards, no streak pressure.

## Tests required
Unit: completion rules, quiz grading (every question kind), cap and quiet-hours maths, catalogue filter building. Integration: age gate by direct URL; parent block; locked paid course never exposes a price or content; version pinning survives a new publish; autosave and resume; quiz answers never appear in any learner payload; cap stops after saving; disabled step; taken-down course; preview mode writes nothing (no enrolment, progress, analytics). Component tests for the step renderers.
