## Requirements
- `checkStart`: implement exactly what the contract comment lists. A `needs_review` course is still available; an open age-policy change event on a required tool gives `tool_on_hold`. A blocked main tool is satisfied by an approved fallback.
- `ToolsYouNeed`: for each tool the name, official link, cost or free tier, minimum age, whether a parent must approve or set up the account, setup-guide link and last-checked date — read from the Register at request time. Learner view shows their approval state and "Ask a parent"; parent view shows approve and decline; staff view shows unverified flags. Never a price for our own plans.
- Tool approvals: request (notifies parents, idempotent while pending), decide, revoke (blocks further setup steps), with `parent_operated` recording that the parent will set up and run the account. Audited.
- Evidence: links (https, `checkPublicUrl`, the tool's allow-list where the step names a tool, a declaration that the linked work shows no real people, never fetched for media, never rendered as a live embed), screenshots, files, video. Uploads go through signed upload URLs then `verifyUpload`; check real file type against the declared type, size limits from `uploads.max_mb`, hash, EXIF stripped from images, filename never trusted. Stored private; downloads by short-lived signed URL only for the learner, linked parents and authorised staff.
- People screening (D3): while `uploads.people_screening_enabled` is off, image and video FILE uploads are never auto-accepted with the `manual` detector: they wait for a human. A detector result of "contains people" rejects automatically, deletes the file at once (keep hash and metadata) and tells the learner kindly what to send instead. Suspected illegal content is quarantined, not deleted, and opens a critical safeguarding case.
- Submission states: draft → submitted → awaiting review / accepted / needs changes. Automated checks (type, size, link safety, text moderation of titles and notes with the local rules moderator in `src/server/ai/moderation.ts` if present, people screening). With `moderation.auto_accept_clean_submissions` on, a clean submission is accepted without a human except the random sample (`moderation.sample_rate`), which is HELD until reviewed (D4). Nothing appears in the portfolio and no certificate is issued while pending or blocked. Rubric self-check is stored with the submission. Resubmission after "needs changes" keeps versions.
- `moderation.ts`: queue items with SLA `due_at` from `moderation.sla_hours` counted inside `moderation.sla_window`; `decideModeration` applies the verdict to the subject (accept or reject a submission, with a kind, specific message to the learner) and `escalate` opens a safeguarding case. Human-only decisions, audited.
- `reports.ts` and `ReportControl`: on every step, course, project and AI output. `someone_in_danger` opens a critical case immediately and shows the fixed crisis signposting; `guide_mismatch` creates a guide-review task; everything else goes to moderation. Calm confirmation; the reporter can see their own reports' status.
- Portfolio: private. Visible to the learner, linked parents and authorised staff only; no public or shareable page at launch. Project page shows the brief, evidence, rubric self-check and status.
- Certificates: issued only when the course is complete AND the required submission is accepted; PDF with `@react-pdf/renderer`; display name is first name or nickname by the learner's choice; unique verify code; `/verify/[code]` shows name, course, date and revoked state only, is `noindex`, and is rate limited; staff can revoke with a reason.
